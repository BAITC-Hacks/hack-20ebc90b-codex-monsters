# Пятиминутная демонстрация части C

Основной показ — HTTP-режим с backend A, запущенный по [runbook](runbook.md). Только synthetic данные. Открывающая фраза: «Показываем живой расчёт заказа, сценарии и сохранение утверждённой версии. Происхождение прогноза показано для выбранного расчёта; старые runs с fixture-v1 сохраняют пометку временного прогноза».

| Время | Действие | Что подтвердить |
|---|---|---|
| 00:00–00:35 | Режим HTTP, два поставщика, склад, as_of, snapshot/run | Синтетическое происхождение и исторический контекст видны; метры и штуки не суммируются |
| 00:35–01:20 | «Проверить или изменить товар» → «Почему столько рекомендовано» | Прочитать серверные компоненты, остаток и поставку. Происхождение прогноза и ограничения явно обозначены |
| 01:20–02:15 | «Что, если…»: 99% или +7 дней → «Сравнить варианты» | Сравнить серверные стоимость и количество с исходным run. Целевой cycle service — не измеренный fill rate. SS не выдумывается, если API не вернул его |
| 02:15–03:40 | Изменить количество с причиной → «Сохранить количество» → «Утвердить и подготовить CSV» → «Скачать CSV» | Новая версия draft, явная ручная дельта, approval конкретной версии. Файл поступает из backend и содержит DEMO watermark |
| 03:40–04:20 | Перезагрузить страницу; затем снова изменить количество | Approval сохраняется на сервере после reload. Последующая правка создаёт новый draft и требует повторного утверждения; старый CSV не становится экспортом новой версии |
| 04:20–04:45 | Исключённый DEMO-016, «Данные» → качество и «Проектные и регулярные продажи» | Неизвестные terms не заменены 1. Новые расчёты используют B; исторический fixture-v1 может иметь пустую таблицу. Показать фактически возвращённые события |
| 04:45–05:00 | Открыть отчёт и назвать следующий шаг | Проверки нового пути, включая live HTTP и restart persistence; актуальные результаты в отчёте. Общую приёмку качества прогноза показывать по доказательствам B; реальной отправки поставщикам нет |

Перед показом проверьте MOQ/multiple выбранного SKU. В проверенном примере DEMO-009 менялся 270 → 275 pcs с причиной; другие runs могут иметь другие количества. UI не подгоняет их под рассказ.

Для отдельного показа project allocation и golden ledger можно явно переключиться в mock: «Далее подготовленные ответы интерфейса, без запуска детектора». В mock golden108 = 100 + 20 + 10 + 30 − 40 − 20 + 8 + 0; ручная правка 120 даёт дельту +12. Поддержаны заранее подготовленные сценарии 99%/+0 и 95%/+7. Не выдавайте этот фрагмент за LIVE.

При сетевой ошибке показать сообщение и повторить чтение. При timeout export сохранить request key и сверить серверный статус; не объявлять файл готовым. При 409 сохранить черновик и пересмотреть актуальную версию. Переход к mock или резервной записи всегда назвать явно. [Отчёт о фактической проверке](acceptance-report.md).
