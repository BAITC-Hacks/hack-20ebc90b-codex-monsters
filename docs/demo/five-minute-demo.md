# Пятиминутная демонстрация части C

Основной показ — HTTP-режим с backend A, запущенный по [runbook](runbook.md). Только synthetic данные. Открывающая фраза: «Показываем живой расчёт заказа, сценарии и сохранение утверждённой версии. Прогноз пока временный fixture-v1; модель и классификация части B ещё не подключены».

| Время | Действие | Что подтвердить |
|---|---|---|
| 00:00–00:35 | Режим HTTP, два поставщика, склад, as_of, snapshot/run | Синтетическое происхождение и исторический контекст видны; метры и штуки не суммируются |
| 00:35–01:20 | Строка предложения, ledger, MOQ и кратность | Прочитать серверные компоненты, остаток и поставку. Временный forecast и его uncertainty явно обозначены |
| 01:20–02:15 | Сценарий 99% или +7 дней, обновить статус | Сравнить серверные стоимость и количество с исходным run. Целевой cycle service — не измеренный fill rate. SS не выдумывается, если API не вернул его |
| 02:15–03:40 | Показать недоступный export; изменить допустимое количество с причиной; утвердить и подготовить CSV | Новая версия draft, явная ручная дельта, approval конкретной версии. Файл поступает из backend и содержит DEMO watermark |
| 03:40–04:20 | Перезагрузить страницу; затем снова изменить количество | Approval сохраняется на сервере после reload. Последующая правка создаёт новый draft и требует повторного утверждения; старый CSV не становится экспортом новой версии |
| 04:20–04:45 | Исключённый DEMO-016, качество данных и вкладка проектов | Неизвестные terms не заменены 1. В LIVE project table пока пустая с model_version: B не подключён, детектор не заявляется работающим |
| 04:45–05:00 | Открыть отчёт и назвать следующий шаг | 123 теста, включая live HTTP и restart persistence. Осталось подключить B и провести общую приёмку качества прогноза; реальной отправки поставщикам нет |

Перед показом проверьте MOQ/multiple выбранного SKU. В проверенном примере DEMO-009 менялся 270 → 275 pcs с причиной; другие runs могут иметь другие количества. UI не подгоняет их под рассказ.

Для отдельного показа project allocation и golden ledger можно явно переключиться в mock: «Далее подготовленные ответы интерфейса, без запуска детектора». В mock golden108 = 100 + 20 + 10 + 30 − 40 − 20 + 8 + 0; ручная правка 120 даёт дельту +12. Поддержаны заранее подготовленные сценарии 99%/+0 и 95%/+7. Не выдавайте этот фрагмент за LIVE.

При сетевой ошибке показать сообщение и повторить чтение. При timeout export сохранить request key и сверить серверный статус; не объявлять файл готовым. При 409 сохранить черновик и пересмотреть актуальную версию. Переход к mock или резервной записи всегда назвать явно. [Отчёт о фактической проверке](acceptance-report.md).
