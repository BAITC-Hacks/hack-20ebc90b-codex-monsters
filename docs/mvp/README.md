# Старт команды: сильный MVP до 6:00

Всего три исполнителя и 225 мин с 2:15. Пользователь управляет направлением, его Codex выполняет A. Backend и общие контракты уже реализуются: [статус A и подключение B/C](status-a.md). Готовность всех частей подтверждается совместной приёмкой.

**Все работают в `main`, без новых веток, worktree и PR.** Предыдущие branch-инструкции отменены пользователем. Для запуска backend используйте [корневой README](../../README.md); B импортирует `ekt.contracts`, C использует `/docs`, `/openapi.json` и HTTP `/v1/*`.

1. Всем прочитать [общий план](master-plan.md) и [контракты](contracts.md).
2. Раздать каждому один документ и скопировать его последний раздел «Стартовый prompt» в свой Codex:
   - **A, пользовательский Codex:** [backend, расчёт заказа, интеграция](participant-a-platform-integration.md).
   - **B, участник2:** [данные и прогноз](participant-b-data-forecast.md).
   - **C, участник3:** [интерфейс и демо](participant-c-ui-demo.md).
3. Соблюдать [правила Git и передачи работы](git-workflow.md).
4. Сдавать по [общей приёмке и demo script](acceptance-demo.md).

Первые35мин — shared types/samples. Первый actual end-to-end — кT+60. Freeze5:20, release5:40, финальные20мин — репетиция. Текущий остаток времени сверять с дедлайном, не начинать новый225-минутный период после чтения.

Реальные supplier данные не нужны для начала: общий synthetic fixture позволяет всем работать независимо. Новые сырые выгрузки в Git не добавлять; уже внесённые другим участником файлы самостоятельно не удалять. Если данных не хватает, интерфейс показывает ограничение, а не придуманную достоверность.
